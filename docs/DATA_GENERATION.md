# IntentX Synthetic Data Generation Protocol

## Objective

AI systems may assist in generating candidate natural-language
utterances for the IntentX dataset.

AI-generated examples are not automatically considered ground truth.

## Source Dataset

The manually curated seed dataset establishes the semantic boundaries
for each IntentX intent class.

## Generation Rules

Candidate examples should contain realistic linguistic variation,
including:

- short requests
- complete sentences
- polite requests
- technical terminology
- beginner terminology
- alternative verbs
- alternative word order
- realistic Linux paths
- realistic service names
- realistic package names
- realistic process IDs

Generated examples must preserve the intended semantic meaning.

## Prohibited Generation Patterns

Avoid:

- trivial word substitution
- excessive template repetition
- meaningless sentences
- unrealistic Linux operations
- unsupported intents
- invented IntentX capabilities
- arbitrary shell scripts
- shell pipelines
- command substitution
- unrestricted command strings

## Safety

Generation of a natural-language example does not imply that the
corresponding operation is safe to execute.

Risk assessment and authorization remain separate components.

## Multi-Model Generation

Candidate examples may be proposed by multiple AI systems.

The generation source should be recorded when practical.

Examples generated by different models must still pass the same
validation and review process.

## Acceptance Pipeline

Candidate example

→ schema validation

→ label validation

→ entity validation

→ exact duplicate detection

→ near-duplicate analysis

→ semantic review

→ acceptance or rejection

Only accepted examples may enter the training dataset.

## Target

The development target is approximately 100 reviewed examples per
intent class where practical.

For the current 21-class catalog, this corresponds to approximately
2,100 examples.

Dataset quality takes priority over reaching an exact row count.
