# IntentX Dataset Specification

## 1. Purpose

The IntentX dataset trains and evaluates the natural-language intent
classification component and provides ground-truth annotations for
later entity-extraction experiments.

The dataset does not directly authorize or execute Linux commands.

## 2. Dataset Unit

Each row represents one natural-language user request.

Example:

Text:
restart the nginx service

Intent:
service_management

Action:
restart

Entities:
{"SERVICE": "nginx"}

## 3. Schema

### example_id

Unique immutable identifier for the example.

Format:

IX000001

### text

Natural-language request submitted by a user.

### intent

Ground-truth intent label.

The label must exist in:

configs/intent_catalog.yaml

### action

Ground-truth action associated with the request.

The action must be valid for the corresponding intent.

### entities

Ground-truth entities encoded as JSON.

Example:

{"PID": "4321"}

### source

Origin of the example.

Initial permitted values:

- curated
- synthetic_reviewed

Synthetic examples shall not automatically be treated as valid simply
because they were generated by an AI system.

### split

Dataset partition.

Permitted values after final splitting:

- train
- validation
- test

## 4. Quality Requirements

Every example shall:

1. Have a unique example ID.
2. Contain non-empty natural-language text.
3. Use an intent defined in the intent catalog.
4. Use an action valid for that intent.
5. Contain valid JSON in the entities field.
6. Contain required entities where applicable.
7. Avoid exact duplicate text.
8. Avoid contradictory labels.
9. Be reviewed before inclusion in the final dataset.

## 5. Linguistic Diversity

Examples should include realistic variations such as:

- direct requests
- polite requests
- short requests
- longer requests
- alternative vocabulary
- different word order
- operational terminology
- beginner terminology

Example:

show disk space

how much storage is available

can you check how much disk space is left

display filesystem usage

These may represent the same intent.

## 6. Safety-Relevant Diversity

The dataset should contain examples that distinguish semantically close
but operationally different requests.

Examples:

check nginx status
→ service_inspection

restart nginx
→ service_management

show process 4321
→ process_inspection

stop process 4321
→ process_termination

show files in /tmp
→ file_listing

delete /tmp/report.txt
→ file_delete

## 7. Out-of-Scope Examples

The dataset shall contain meaningful out-of-scope examples.

Examples include:

write an email

tell me a joke

what is the weather today

explain machine learning

The model should learn that not every sentence belongs to a Linux
operation.

## 8. Ambiguous Requests

Ambiguous requests require special treatment.

Example:

fix nginx

This does not uniquely specify whether the user intends to inspect,
restart, reconfigure, reinstall, or perform another action.

Such examples should not be incorrectly forced into a specific
executable intent.

Ambiguous examples may be represented as out_of_scope in the baseline
classifier or maintained as a dedicated evaluation set for
clarification behavior.

## 9. Data Leakage Prevention

Near-identical paraphrases shall not be distributed across training and
test sets in a way that artificially inflates performance.

Examples derived from the same template or paraphrase family should be
grouped before splitting where practical.

## 10. Dataset Splitting

The final dataset shall use separate:

- training data
- validation data
- test data

The test set shall not be used for model fitting or threshold tuning.

## 11. Evaluation

Intent classification evaluation shall include:

- accuracy
- macro precision
- macro recall
- macro F1
- per-class precision
- per-class recall
- per-class F1
- confusion matrix

Accuracy alone shall not be considered sufficient.

## 12. Reproducibility

Dataset-generation and splitting procedures shall use documented
configuration and fixed random seeds where applicable.

Dataset versions used for experiments shall be identifiable.

## 13. AI-Generated Data

AI tools may assist in proposing linguistic variations.

AI-generated examples must be treated as candidate data rather than
automatically accepted ground truth.

Examples shall be validated against the intent catalog and reviewed for:

- correct intent
- correct action
- correct entities
- realism
- duplication
- ambiguity
- leakage risk

## 14. Initial Dataset Target

The initial development dataset should aim for approximately 100
reviewed examples per intent class where practical.

With 21 current intent classes, this corresponds to approximately
2,100 examples.

The exact final number is less important than label quality,
linguistic diversity, and evaluation integrity.
